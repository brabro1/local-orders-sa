# قاعدة البيانات والطلبات (Firebase)

الخادم الحقيقي لتطبيق الطلبات: أين تُحفظ الطلبات، ومن يقدر يقرأها، وكيف تتغيّر حالتها.
يشتغل الحين على **محاكي Firebase في الجهاز فقط**. ما فيه مشروع Firebase حقيقي ولا بيانات حقيقية.

**الدفع الإلكتروني مو هنا للحين.** كل الطلبات كاش أو شبكة في المحل (`pay: 'cod'`)، والطلب يصير «مدفوع» لما الموظف يضغط «تم التسليم».

## الفكرة باختصار

- التطبيق (جوال العميل أو جهاز المحل) **يقرأ** من قاعدة البيانات مباشرة، ويوصله أي تغيير لحظيًا.
- التطبيق **ما يكتب** الطلبات بنفسه أبدًا. كل تغيير يمر على دالة في الخادم (`functions/index.js`)، وهي تحسب السعر من قائمة المحل، وتعطي رقم الطلب، وتتأكد إن الخطوة صحيحة. يعني ما أحد يقدر يغيّر سعر أو يضيف ختم ولاء من جواله.
- محل واحد = مستند واحد، وكل شيء تحته. المغسلة الثانية تنضاف كمستند جديد، مو نسخة جديدة من الكود.

## شكل البيانات

| المسار | فيه | مين يقرأ |
|---|---|---|
| `shops/{shopId}` | الاسم، القائمة والأسعار، الأحياء، المواعيد، رسوم التوصيل، الباقات، أسباب الرفض، ومفاتيح «مفتوح / التنظيف الجاف / مواعيد اليوم» | الكل (هذا اللي يعرضه التطبيق) |
| `shops/{shopId}/orders/{n}` | طلب واحد، و`n` رقمه اللي يشوفه العميل والموظف | جهاز المحل: كل الطلبات. العميل: طلباته فقط |
| `shops/{shopId}/customers/{+9665…}` | أختام الولاء، والمكافآت، والباقة الشهرية، وعدد الطلبات | جهاز المحل، والعميل نفسه |
| `shops/{shopId}/slotLoad/{تاريخ_موعد}` | كم طلب محجوز في كل موعد استلام (رقم فقط) | الكل |
| `shops/{shopId}/private/*` | رمز PIN مشفّر، ومحاولات الدخول، وعدّاد أرقام الطلبات | لا أحد (الخادم فقط) |

جهاز المحل يقدر يغيّر شيء واحد بنفسه: مفاتيح «مفتوح / التنظيف الجاف / مواعيد اليوم». الأسعار ما تتغيّر من الجهاز.

## الدوال (كل وحدة يناديها التطبيق)

| الدالة | مين | وش تسوي |
|---|---|---|
| `placeOrder` | العميل (برقم جوال متحقق منه برمز SMS) | طلب استلام من البيت أو طلب يجيبه بنفسه. تتأكد من الحي والموعد والحد الأدنى، وتحسب السعر والخصومات والباقة والمكافأة |
| `cancelOrder` | العميل | يلغي طلبه لو ما انقبل للحين، ويرجع له الموعد والمكافأة والقطع |
| `staffLogin` | جهاز المحل | دخول برمز PIN. بعد 5 محاولات غلط يتقفل 15 دقيقة |
| `advanceOrder` | جهاز المحل | ينقل الطلب خطوة وحدة للأمام. ولما يوصل «تم التسليم» يضيف ختم ولاء |
| `saveCount` | جهاز المحل | جرد القطع والفاتورة النهائية، ويعيد حساب الباقة والمكافأة |
| `rejectOrder` | جهاز المحل | رفض بسبب من أسباب المحل، ويرجع للعميل اللي أخذه الطلب |
| `saveWalkin` | جهاز المحل | «طلب جديد في المحل»، أو تعديله |

خطوات الطلب:
- استلام من البيت: جديد ← مقبول ← المندوب في الطريق ← تم الجرد ← قيد الغسيل ← جاهز ← في الطريق للعميل ← تم التسليم
- يجيبه العميل بنفسه أو طلب في المحل: جديد ← مقبول ← تم الجرد ← قيد الغسيل ← جاهز ← تم التسليم

## التجربة على جهازك

تحتاج Node.js 22 أو أحدث، وJava 21 (المحاكي يحتاجها).

```bash
cd firebase
npm install
(cd functions && npm install)
npm test          # يشغّل المحاكي، ويجرّب كل شيء، ويقفله
npm run test:unit # حسابات الأسعار فقط، بدون محاكي (ثوانٍ)
```

لو تبي تشوف البيانات بعينك: `npm run emulators` (يفتح لوحة المحاكي على http://localhost:4000)، وفي نافذة ثانية `FIRESTORE_EMULATOR_HOST=127.0.0.1:8080 npm run seed` يضيف «مغسلة تجريبية» برمز PIN ‏`2468`. هذا الرمز للمحاكي فقط.

## الملفات

```
firebase.json, .firebaserc   إعداد المحاكي (مشروع demo-local-orders، ما يتصل بأي مشروع حقيقي)
firestore.rules              مين يقرأ ويكتب وش
firestore.indexes.json       فهارس «طلباتي» و«طلبات المحل حسب الحالة»
functions/index.js           الدوال
functions/src/pricing.js     حساب السعر والخصومات والباقة والمكافأة (نفس منطق النموذج)
functions/src/flow.js        خطوات الطلب، وتاريخ الرياض، والمواعيد، وأرقام الجوال
functions/src/pin.js         تشفير رمز PIN
seed/                        «مغسلة تجريبية» بأسعار النموذج الافتراضية
tests/                       الاختبارات
```

## الباقي قبل التشغيل الحقيقي

1. ~~ربط الواجهة~~: صار في مجلد `app/` (صفحة العميل وصفحة المحل).
2. **مشروع Firebase حقيقي:** بعد ما نقرّر مكان حفظ البيانات (الدمام `me-central2` أو غيرها)، لأن مكان القاعدة **ما يتغيّر بعد الإنشاء**. الدوال تحتاج خطة Blaze (الدفع حسب الاستخدام). المنطقة مكتوبة في مكان واحد: `REGION` في `functions/index.js` [غير متحقق: توفّر الدوال وFirestore في الدمام].
3. **رسائل رمز التحقق:** دخول العميل برقم الجوال يحتاج SMS، وتكلفتها [غير متحقق] ومزوّدها قرار مفتوح في الخطة.
4. **App Check:** حماية الدوال من الطلبات الآلية قبل الإطلاق.
5. **بيانات المحل الحقيقية:** القائمة والأسعار ورمز PIN تنحط في المشروع الحقيقي مباشرة، **مو في هذا المستودع** (المستودع عام).
6. **الدفع الإلكتروني:** في مرحلة لاحقة، حسب الخطة في نوشن.
